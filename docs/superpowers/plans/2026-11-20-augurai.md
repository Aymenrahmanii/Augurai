# Augurai Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use **superpowers:executing-plans** (Native: Aymen chose it on 2026-11-20). Implement every task in this session, in order. After Task 19, run one whole-branch review with superpowers:requesting-code-review. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Augurai. It does two jobs:
- **The radar,** fully autonomous. It collects AI models, benchmarks, repos, skills, MCP servers, people, practices and job trends every 6 hours, publishes a public static site, and emails a morning briefing.
- **The coach,** local and weekly. It reviews Aymen's Claude Code sessions and proposes improvements, which Aymen approves one by one.

**Architecture:** A Python package (`augurai`) run by a GitHub Actions workflow.
- **Every run:** deterministic Python collects the sources, ranks them, runs discovery and builds the site.
- **The morning run** adds one headless Claude Code session (`anthropics/claude-code-action` with Aymen's subscription OAuth token). It reads `work/enrich_input.json` and writes `work/enrich_output.json`, which Python validates and merges. If the Claude step fails, everything else still ships without the enrichment.
- **The coach** runs locally via `claude -p`.

**Tech Stack:** Python 3.12, uv, httpx, pydantic v2, jinja2, feedparser, markdown, tzdata; pytest, respx, ruff; GitHub Actions + GitHub Pages; Gmail SMTP.

**Spec:** `docs/superpowers/specs/2026-11-20-augurai-design.md` (read it before starting any task).

## Plan decisions beyond the spec

- `best_at` is computed **deterministically** from benchmark scores (Task 6). Claude writes only `use_cases` and `avoid_for`. This keeps the benchmark consistent between runs.
- **Cron schedule:**
  - Morning: `30 4 * * *` UTC (05:30 Tunis). Actions queue delays can be 30–60 minutes, so this lands before 07:00.
  - Refresh: `0 10,16,22 * * *` UTC.
- **The CLI has two cloud phases,** `augurai collect` and `augurai finish`, because the Claude step runs between them as a separate workflow step. Other commands: `augurai build` (local preview) and `augurai coach`.

## Review Focus

1. **A rerun of the morning workflow** (manual re-run or a late cron) must not send a second email for the same local date. Test in Task 13.
2. **Claude output that is missing, malformed, or partly valid** (unknown ids, over-long text, wrong types): keep the valid parts, drop the rest, never crash, and record `enrichment="failed"` or `"partial"` with a note. Test in Task 12.
3. **A source that returns HTTP 200 with an empty or changed payload** counts as a failure. Existing data is kept, and nothing is deleted because one fetch came back empty. Test in Task 5 (framework) and Task 6 (catalog merge).
4. **The first run with an empty `data/`:** no division by zero in velocity, and the briefing says "baseline established" instead of listing hundreds of "new" items. Test in Task 11.
5. **Transcripts containing secrets, huge pasted blobs, or malformed JSONL lines:** redact the secrets, truncate the blobs, skip bad lines. Test in Task 17.

### Task 5: Source framework

**Files:**
- Create: `src/augurai/sources/base.py`, `src/augurai/sources/__init__.py`, `tests/sources/test_base.py`

**Interfaces:**
- Consumes: `Settings`, `RawItem`, `SourceHealth`.
- Produces, in `augurai.sources.base`:
  - `class SourceError(Exception)`
  - `@dataclass class SourceContext: settings: Settings; http: httpx.Client; now: datetime; env: Mapping[str, str]`
  - `class Source(Protocol): name: str; required_env: tuple[str, ...]; def fetch(self, ctx: SourceContext) -> list[RawItem]: ...`
  - `make_client() -> httpx.Client`:
    - timeout 20s
    - `httpx.HTTPTransport(retries=3)`
    - header `User-Agent: augurai/0.1`
    - adds `Authorization: Bearer $GITHUB_TOKEN` only for requests to `api.github.com` (done in the GitHub adapters, not globally)
  - `@dataclass class SourceRun: items: list[RawItem]; ok: list[str]; failed: list[str]; skipped: list[str]; health: dict[str, SourceHealth]`
  - `run_sources(sources: Sequence[Source], ctx: SourceContext, health: dict[str, SourceHealth]) -> SourceRun`. Rules:
    - Missing required env → **skipped**. Health is not counted as a failure, and `last_error` is set to `"missing env: X"`.
    - An exception, **or an empty result list** → **failed**: `consecutive_failures += 1`, `last_error` set to the message (truncated to 300 chars).
    - Success → `consecutive_failures = 0`, `last_success = now`.
    - An exception never propagates.
- Produces, in `augurai.sources`: `all_sources(settings: Settings) -> list[Source]`. It returns `[]` for now; Tasks 6–10 append to it.

### Task 9: People and discovery

**Files:**
- Create: `src/augurai/domain/people.py`, `tests/domain/test_people.py`

**Interfaces:**
- Consumes: `Person`, `WorkItem`, `ScorePoint`, `RawItem`, `Entity`, `Settings`.
- Produces:
  - `people.seed(existing: dict[str, Person], settings: Settings) -> dict[str, Person]`: makes sure every seed person exists with `status="seed"`. Seed links from config overwrite stored ones.
  - `people.attach_work(people: dict[str, Person], items: list[RawItem]) -> dict[str, Person]`:
    - Items with `extra.person_id` become `WorkItem`s, deduplicated by url, keeping the latest 20.
    - Updates `last_active` from them.
  - `people.candidate_signals(items: list[RawItem], entities: dict[str, Entity], rising_ids: list[str]) -> dict[str, float]`, keyed by GitHub login or HN user. Signal weights:
    - owner of a rising entity: `+3.0` each
    - author of an HN item with points ≥ `hn_min_points`: `+1.0` each
    - linked from a followed or seed person's post (`extra.linked_people` from Task 8, counted only for items with an `extra.person_id`): `+1.0` each
  - `people.update_discovery(people: dict[str, Person], signals: dict[str, float], today: date, settings: Settings) -> tuple[dict[str, Person], list[str], list[str]]`. Returns `(people, promoted_ids, demoted_ids)`.

  **The discovery algorithm:**
  - **New candidates:** a signal key that isn't a known person creates `Person(id=key, name=key, status="rising", links={"github": f"https://github.com/{key}"})`, but only when its signal is ≥ 1.0.
  - **Score:** the sum over the last 30 days of `score_history`, plus today's signal. Append `ScorePoint(today, signal)` at most once per day, and drop points older than 30 days.
  - **Promotion:** `above_threshold_runs` goes up by 1 when the score is ≥ `promote_threshold`, and resets to 0 otherwise. A `rising` person whose `above_threshold_runs` reaches `promote_consecutive_runs` becomes `followed` and is added to `promoted`.
  - **Dormancy:** a `followed` person whose `last_active` (or last nonzero ScorePoint) is older than `dormant_days` becomes `dormant` and is added to `demoted`. A `dormant` person who gets above threshold again returns to `rising`.
  - **Seeds** never change status.
  - **Pruning:** `rising` people with a score of 0 for 30 days are deleted, so the file doesn't grow forever.

  - **Model notes:** kept only for known models, at most 5 entries each.
  - **Briefing:** validated, and every `body_md` is capped at 1200 chars.
  - **Status:** `"partial"` when anything was dropped (the note lists counts), `"ran"` when nothing was.
